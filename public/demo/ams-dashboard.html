What this demo is

A working recreation of the AMS monthly performance dashboard described in the case study. The run is simulated and the content is invented; the structure, the rules and the gate are the real ones.

The four decisions it makes visible

1. Counting is deterministic; only synthesis goes to a model — every panel carries a rule or model badge.

2. The second pass reads the generated sheets, not the raw tasks — sheets 4–6 cite the cell they came from.

more

3. Written analysis runs on the worst decile only — 4 of 38 delayed tasks. The other 34 arrive as a row and a link.

4. Nothing publishes unsigned, and the signer must own the affected work. Unconfirmed causes publish as “cause not confirmed”, never blank.

All tasks, names, comment threads, causes and figures on this page are invented for the demo. No task, customer or individual’s performance data appears here. Per-project coverage in this single May run reads 91 / 86 / 82 / 78 per cent; the case study quotes 79 per cent for Project D because it averages three runs.
